# FFmpeg GUI 产品与技术设计

版本 0.2

日期 2026 年 10 月 14 日

状态 产品设计与功能化原型实现说明

交付形态 跨平台桌面应用

工作名称 FFmpeg Workbench

FFmpeg Workbench 面向需要直观配置 FFmpeg、同时保留完整命令能力的用户。产品采用本地桌面界面和本机 FFmpeg 执行引擎，目标覆盖输入、输出、流、编解码器、滤镜、格式、协议、设备及其参数。中文为默认界面，保留英文参数名和原始帮助，便于查阅与复现。

核心方案是将当前二进制的能力目录、有序命令文档和可视化编辑器组合起来。用户入口以“要完成什么”为中心，常用参数组合成功能，低频参数按用途提供中文说明与可选择的配置。原始参数目录用于能力对账和专业排查，不要求普通用户先理解参数名。命令视图与图形界面共享同一个文档；未知参数保真保存，并作为覆盖缺口报告。

v0.2 原型已实现六个常用功能入口、19 个常用控件、三步骤操作和 28 项低频图形配置，命令默认折叠。当前功能流程支持一个素材、一个本地输出，已在 macOS Apple Silicon 原生桌面验证；全量参数、复杂处理和 Windows/Linux 实机验证仍属于后续工作。引擎发现的 2843 条参数不等于这些能力已经完成图形配置。以下章节同时保留完整产品的设计目标，不能将规划项视为本版已经实现。

## 1 产品目标和范围

### 产品目标

1. 用户通过用途和预期效果找到功能，理解设置的影响，以选择、开关或数值配置完成任务，无须认识 FFmpeg 参数名。
2. 图形操作不丢失高级设置，不擅自调整参数顺序，不隐式改变流选择和编码方式。
3. 支持多个输入、多个输出及每个输出流独立配置，支持复杂音视频处理关系。
4. 展示实际执行参数、实时进度、日志和产物信息，使任务可以复现和排错。
5. 通过动态能力发现和版本规则包适配 FFmpeg 更新，不依赖一份长期固定的参数清单。
6. Windows、macOS、Linux 使用同一份工程和交互模型；平台特有的设备与硬件功能按实际能力显示。

### 全功能参数的正式定义

覆盖对象是用户选定的 ffmpeg 可执行文件在其版本、编译配置和平台下提供的命令行能力，包括通用选项和组件私有选项。不存在于该构建中的编码器、滤镜或设备，显示为不可用，不能靠 GUI 补出相应能力。

完整覆盖需要同时满足：

- 全量目录：声明支持的构建中，每个发现的组件和参数都可检索，有出处和状态。
- 全量配置：每个可配置参数都有可添加、重复、排序、禁用和编辑的参数实例，以及明确的作用域。
- 复杂值编辑：流映射、选择器、滤镜图、字典、节目和流组等复合结构有对应编辑器；表达式允许文本输入，但提供补全、变量说明和校验。
- 命令保真：导入和编辑不静默丢项，不把合法的重复参数合并成单值。
- 场景验证：通过代表性任务的真实执行和产物检查，验证相关参数组合的行为。

原始命令框和未知参数透传用于兼容扩展，不计入结构化可视化覆盖率。存在未解析参数或缺少作用域规则时，版本说明必须列出缺口，不宣称完整覆盖。功能可配置与本机可运行分别记录，硬件、权限和外部服务不满足时仍能保存配置。

FFmpeg 官方提供完整及组件定向帮助，但帮助文本没有提供足以描述所有组合关系的稳定机器接口。参数语义需要结合匹配版本的工具定义与规则维护。[FFmpeg 参数帮助](https://ffmpeg.org/ffmpeg.html#Generic-options)、[工具参数定义](https://github.com/FFmpeg/FFmpeg/blob/master/fftools/ffmpeg_opt.c)

### 首期边界

首期实现桌面应用和本地任务运行。ffprobe 用于媒体分析，ffplay 可选作外部播放工具；首期的全参数承诺针对 ffmpeg，不自动延伸到 ffprobe 和 ffplay 的完整 CLI。

工程保留未来接入远程 Runner 的接口，但首期不提供云转码、多人协作或公网控制台。任意 shell 脚本、管道编排和命令替换属于独立的脚本能力，不属于单个 ffmpeg 调用的参数覆盖范围。

## 4 信息架构和交互

### 交互原则

默认界面表达用户要做的事情和会得到的结果。常用设置直接出现在对应功能中；低频设置也使用中文用途、说明和图形控件。参数名和命令用于核对、复现及排查，不承担普通用户理解功能的任务。

选项给出实际影响，例如“文件更小，细节会减少”“只改变显示比例，不裁剪画面”。默认值足以完成常规任务；与格式、编码器或素材不兼容时说明原因，保留用户原有配置。切换功能不会隐式丢弃无法表达的高级设置。

### 六个功能入口与三个步骤

| 功能入口 | 用户目的 | 主要图形操作 |
| --- | --- | --- |
| 压缩视频 | 文件更小，方便发送和保存 | 画质优先/均衡/体积优先、画面尺寸、输出格式 |
| 转换格式 | 适配播放设备或交付要求 | MP4/MKV/MOV/WebM、画质倾向；当前采用重新编码 |
| 截取片段 | 保留需要的一段 | 开始时间、保留时长、输出格式 |
| 调整画面 | 调整尺寸或拍摄方向 | 等比例缩放、旋转 90°/180°、左右镜像、上下翻转、帧率 |
| 提取音频 | 单独保存视频里的声音 | MP3/WAV/FLAC、声音码率、采样率、音量、可选片段 |
| 去除声音 | 生成只有画面的静音视频 | 移除音轨、输出格式、画面尺寸 |

每个入口复用三个步骤：

1. 选择你的素材：选一个本地视频或音频，显示文件名和位置，原文件保留。内置 5 秒无声测试画面用于体验；音频功能要求有音轨的真实素材。
2. 调整效果：优先展示当前功能需要的设置；其他常用画面、声音和截取设置可在本步骤展开。片段时间支持秒数或时分秒；缩放按高度保持比例。画质倾向描述质量与体积的取舍，不承诺固定文件大小。
3. 保存到哪里：选择新输出文件，核对摘要，开始处理或加入当前串行队列。已有文件拒绝覆盖，名称冲突需要另选名称。

当前素材正在读取或读取失败时禁止入队。读取失败在素材块展示具体原因，并提示用“更换素材”重新选择；原生选择成功时递增素材修订号（sourceRevision），即使同一路径也重新探测，避免保留旧错误状态。工程内的文件路径引用不能替代系统文件选择，读取失败也不能仅凭现象确定为系统权限问题。探测成功但时长未知的素材仍允许处理，并使用无百分比和剩余时间的进度显示。

### 同一个工程的功能、设置和命令视图

功能面板、更多设置和折叠命令读取同一个有序 CommandDocument。功能操作通过已验证规则生成和修改对应参数；更改画质倾向与自定义目标码率时明确切换控制方式，不能叠加互相覆盖的设置却显示另一个效果。

打开旧工程时保留未知 token、参数顺序和多个输入输出。对于未映射的参数显示保留提示；复杂滤镜、未经解释的命令片段、特殊流选择或不能无损表达的滤镜顺序使功能面板转为只读，并说明原因。用户仍可保存原工程，再用新示例或普通素材创建可编辑任务。该保真回退不计入图形配置覆盖率，也不代表当前 Runner 可以执行该工程。

后续每个低频参数都应补齐用途、作用对象、控件、适用条件和实际验证，逐步扩展“更多设置”，而不是将发现的 CLI 清单直接当作面向普通用户的配置界面。

### 后续复杂场景的交互目标

多输入输出提供素材与目标轨道的映射操作，复杂处理提供滤镜节点、端口和表达式辅助，批量处理提供模板和逐条产物检查。可选专业模式可提供参数实例顺序、作用域及滤镜图工作台；低频功能在普通模式仍必须提供可理解的语义控件，不能只留下原始参数清单。后续命令导入需先在临时缓冲区解析，成功后一次应用，失败时保留原工程。以上尚未全部实现在 v0.2。

应用预设会显示新增、替换和删除的设置。预设不能静默覆盖已有流映射或高级参数。

## 5 参数目录和动态能力发现

### 数据来源

能力目录由三部分组成：

- 当前二进制输出：确认实际包含的选项和组件。
- 匹配版本的规则包：补充作用域、别名、参数个数、组合语法和已知约束。
- 用户与运行环境探测：确认设备、驱动、权限及短样本运行结果。

当前版本的网上文档用于解释和导航，不能覆盖本机二进制的事实。二进制未提供可靠信息时保留未知状态，禁止由界面臆造范围或默认值。

ffmpeg -h bsf=NAME
ffmpeg -h protocol=NAME
~~~

扫描过程有超时、并发上限、输出大小上限和取消入口。基础目录完成后即可操作，组件详情按需加载。后台完成全量详情扫描后生成覆盖报告。

缓存键包含二进制内容哈希、路径、FFmpeg 与库版本、编译配置、平台架构、探测器和规则包版本，并记录实际加载的共享 libav 库的路径与内容身份。共享库变化使目录和帮助缓存失效；驱动变化主要使硬件运行结果失效。无法确认动态库来源时，能力缓存只在当前会话中可信，不跨次启动复用。任务启动前重新核对引擎环境，不能仅靠相同版本号复用所有结果。

帮助解析器保留原始输出和未解析行，记录证据偏移及解析警告。解析失败进入降级状态，不显示“完整扫描成功”。

### 参数定义

| 字段 | 用途 |
| --- | --- |
| definitionId | 组件类别、组件名、规范参数名组成的唯一标识 |
| spelling 和 aliases | CLI 拼写、别名和来源 |
| arity | 不取值、取一个值、特殊语法或待确认 |
| valueEncoding | 正负 CLI 开关、显式 0/1 布尔值、普通取值等实际编码规则 |
| valueType | 布尔、整数、浮点、枚举、flags、分数、时间、尺寸、颜色、路径、URL、字典、列表、表达式等 |
| constraints | 范围、枚举、单位和可用条件；可为空 |
| defaultRaw | 原始默认值说明，不自动写入命令 |
| scopes | 全局、输入、输出、流、回环解码器、组件实例 |
| syntaxId | 复合值语法解析器标识 |
| editorId | 通用控件或专用编辑器标识 |
| sourceEvidence | 帮助输出、规则版本或官方来源 |
| coverageState | 已发现、可编辑、语义已验证、不支持、待确认 |

相同名称在不同组件中可以有不同含义，不能仅按名称建立全局定义。硬件相关条目另外记录“编译包含”和“运行可用”。

### 元数据补充方案

受控发布构建可提供同构建的元数据辅助程序，通过 AVOptions API 提取类型、范围与子对象信息。它用于增强帮助解析，不能代替 ffmpeg 工具自身的参数定义，也不能把系统中另一套 libav 库当作选定二进制的真实能力。[AVOptions API](https://ffmpeg.org/doxygen/trunk/group__avoptions.html)

## 6 命令文档和核心数据模型

### 有序命令是事实来源

底层保存有序 argv token 序列及其节点归属，上层生成输入输出树、映射表和参数表单。节点归属和结构化值是同一文档中的可编辑投影，通过统一变更操作保持一致。

不能将命令保存为普通参数字典，也不能固定重排为“全局参数、所有输入、所有输出”。FFmpeg 的文件参数通常依附后续输入输出；新版本的回环解码器也有位置及参数分组要求。[命令解析实现](https://github.com/FFmpeg/FFmpeg/blob/master/fftools/cmdutils.c)、[回环解码器](https://ffmpeg.org/ffmpeg.html#Loopback-decoders)

### 核心类型

~~~ts
type CommandDocument = {
  schemaVersion: number;
  revision: number;
  binaryProfileId: string;
  invocationKind: "process" | "inspect" | "diagnostic";
  nodes: CommandNode[]; // 按真实命令顺序保存
  resources: ResourceRef[];
  filtergraphs: FilterGraphDocument[];
};

type CommandToken =
  | { kind: "text"; value: string }
  | { kind: "nativePath"; pathRefId: string };

type CommandNode =
  | OptionOccurrence
  | { kind: "input"; id: string; rawTokens: CommandToken[]; resourceId: string }
  | { kind: "output"; id: string; rawTokens: CommandToken[]; targetId: string }
  | { kind: "loopback"; id: string; rawTokens: CommandToken[]; sourceRef: string }
  | { kind: "opaque"; id: string; rawTokens: CommandToken[]; reason: string };

type OptionOccurrence = {
  kind: "option";
  id: string;
  definitionId?: string;
  rawTokens: CommandToken[];
  spelling: string;
  valueRaw?: string;
  parsedValue?: unknown;
  streamSpecifierRaw?: string;
  scopeRef?: string;
  valueSource: "inline" | "file" | "none";
  enabled: boolean;
  provenance: "user" | "preset" | "import";
  interpretation: "verified" | "inferred" | "opaque";
};

type NativePathRef = {
  id: string;
  platform: "unix" | "windows";
  encoding: "bytes-base64" | "utf16le-base64";
  payloadBase64: string;
  displayText: string;
  relativeHint?: string;
  relocationRequired: boolean;
};
~~~

以上类型描述工程逻辑。原生路径由 Rust 层保存为平台原始字节或 UTF-16 单元，JSON 只保存带平台标记的编码结果；显示文本不能反向替代原始路径。直接 argv 导入的普通参数使用 text token，原生文件选择使用 nativePath 引用，编译时恢复为 OsString。只有能在目标方言无损表示的路径才提供 shell 文本导出；否则提供工程或 argv 资源格式并解释限制。跨平台打开不能将原生字节强转路径，应先重定位。

### 重要不变量

- 每次参数出现都有独立 ID；重复 -map 不去重，覆盖型参数也保留原始出现顺序。
- 未设置与显式设置默认值不同，禁用实例保留在工程但不参与编译。
- 已解析流引用绑定稳定输入输出 ID，编译时再换成索引。
- 输入重排会列出受影响映射；未知片段含未理解的索引时阻止自动重排，允许用户明确修订。
- 多个 -filter_complex 独立保存，滤镜输出标签建立显式引用。
- 画布布局属于展示数据，不影响命令含义。
- 每次修改可撤销；任务提交保存固定文档修订，后续工程修改不改变已排队作业。

## 7 命令编译和导入

### 编译流程

工程变更 → 局部语法与关系校验 → 生成执行计划 → 资源与输出检查 → 生成 argv → 启动进程。

编译结果同时包含可执行路径、argv、工作目录、受控环境变量、输入资源、输出目标、运行限制、引擎指纹和文档修订。界面中的“用户命令”与加入进度通道等设置后的“实际执行命令”分别可见。

运行时参数由计划编译器加入并记录，不能重复插入已有 -progress、-stdin、覆盖策略等设置。与用户设置冲突时明确提示处理方式。

### 三种保真承诺

1. 直接 argv 导入后不编辑：导出相同的 token 值和顺序。
2. 通过图形界面编辑：只改对应节点和必要的已解析引用，其他 token 保留。
3. shell 文本导入：在所选方言支持的单次调用语法范围内，解析与重新导出的 argv 相同；空白和引号外观可以变化。

命令文本只是显示或导入格式。执行使用原生程序与参数数组，不交给 shell 二次解析。

### 未知与不支持语法

遇到未知选项不能猜下一 token 一定是参数值，因为它也可能是输出地址。保留原始片段，显示待确认的参数个数与作用域，允许人工标注；标注结果属于该工程，不自动成为全局规则。

变量展开、通配符展开、命令替换、重定向和 shell 管道不自动执行。导入器显示相关片段与处理建议，用户可以先展开为明确参数，或将多个调用分别建立作业。普通参数内部的字面字符仍按所选方言正确处理。

高级 token 编辑器保留扩展能力，但未知片段不计入可视化覆盖。无法解析的区域不会被重新格式化或静默删除。

### 作用域示例

~~~text
ffmpeg -ss 00:01:00 -i input.mp4 -t 10 output.mp4
ffmpeg -i input.mp4 -ss 00:01:00 -t 10 output.mp4
~~~

界面分别呈现输入前定位和输出范围处理，不能只显示一个含义模糊的“开始时间”。拖动 -ss 跨输入边界属于语义修改，需要显示影响。

再如 -c copy 与后续 -c:v:1 libx264，必须保留选择器和覆盖顺序；第二条规则可能只改变匹配的输出视频流，不能将两条设置合并为一个编码器下拉框。

## 8 流映射和复合参数编辑

流映射表按“输入资源与流 → 可选滤镜标签 → 输出流”呈现。每个输出支持自动选择或显式映射，自动选择显示为运行前的推断，不伪造为已固定的真实结果。

专用编辑器覆盖：

- 正向、排除和可选映射，以及按类型、索引、节目、元数据等方式选择流。
- 每个输出流的编码器、copy、语言、标题、disposition 和私有参数。
- 全局与流元数据、章节映射、附件、节目和流组。
- BSF 链、格式复合字典、外部编码器参数字典。
- 硬件设备初始化、设备派生、软件帧与硬件帧传输关系。

参数取值中的列表、flags 和字典保持原始顺序及原始字符串，结构化编辑器只修改已理解的元素。不能因冒号或逗号出现就统一切分，必须使用对应语法规则。

复合语法建立独立清单，至少区分外层参数、结构解析、已知内层键、值校验和未知扩展键。例如外部编码器字典、tee 子输出和嵌套协议，外层字典可编辑不代表内部参数已经全部覆盖。M0 按参考构建所含外部组件的版本引入对应规则；无法枚举或未验证的内部键明确列为缺口，不以外层 100% 指标替代。

布尔值也依参数定义编译：CLI 的 -foo 与 -nofoo 开关不等同于 AVOption 的 -option 0 或 1。控件读取 valueEncoding，保留导入拼写，并分别验证 true、false 和重复覆盖。[FFmpeg AVOptions](https://ffmpeg.org/ffmpeg.html#AVOptions)

## 9 滤镜节点和表达式

### 图模型

每个滤镜实例保存组件名、实例 ID、参数实例、输入输出端口、标签、链接顺序、隐式连接、参数文件引用和原始片段。支持音频、视频、source、sink、动态端口、多输入多输出和多个复杂图。

滤镜图是有向图，允许环和同一节点之间多条连接，不能使用“必须无环”作为通用规则。任务子步骤的依赖图可以另设为有向无环图。[FFmpeg 滤镜图定义](https://ffmpeg.org/ffmpeg-filters.html#Filtergraph-description)

节点画布提供等价连接表，便于键盘操作和阅读大型图。自动布局只调整坐标；复制节点重新生成实例 ID，标签冲突需显式解决。

### 参数和表达式

常用裁剪、水印、颜色、缩放等提供直接操作控件，所有滤镜实例都能打开参数面板。表达式编辑器提供当前上下文的变量、函数、单位、补全和语法检查；不能在前端把任意表达式当 JavaScript 执行。

时间启用、运行时命令和动态参数控件只对实际支持这些能力的滤镜开放。任意滤镜不统一承诺关键帧或运行时修改。

无法安全解析的子图显示为原始图片段，保留位置和文本；相应内容标记为未完成可视化支持。已知复合语法的专用编辑器仍需按覆盖清单完成。

转义分别处理参数值、filtergraph 和复制命令所需的 shell 层；实际 argv 执行跳过 shell 层，防止双重转义。[FFmpeg 引号与表达式规则](https://ffmpeg.org/ffmpeg-utils.html)

## 10 媒体探测和预览

### 媒体探测

使用匹配引擎配置的 ffprobe JSON 输出获取容器、流、章节和元数据。默认仅读取基础信息，不自动扫描全部帧或 packets；深度分析以独立任务启动，并提供取消入口。

媒体缓存以资源身份、大小、修改时间及探测参数区分；网络源设置时限和大小上限。设备、受保护地址及可能发生副作用的资源不自动连接。[ffprobe JSON 与媒体信息](https://ffmpeg.org/ffprobe.html#Main-options)

### 两类预览

| 类型 | 用途 | 约束 |
| --- | --- | --- |
| 滤镜预览 | 检查裁剪、水印、合成、画面和音频处理效果 | 不用于判断 CRF、码率或最终编码质量 |
| 真实编码样片 | 使用选定编码器和参数生成短片段 | 仍受片段长度、预滚和统计范围影响 |

低分辨率代理和快速定位只能用于明确标注的快速预览。严格样片尽量保留实际处理链、原始尺寸、像素格式和色彩参数；需要改变图或时间范围时记录差异。

时序依赖、全局统计、两遍分析和直播滤镜按能力要求预滚或全段分析，不能保证任意时间点即时准确预览。HDR 显示、色彩转换和浏览器播放能力也可能影响观察结果，预览界面显示实际播放链条件。

设备采集、推流、网络写入和未知外部资源不自动试跑。用户主动生成样片时，预览输出重定向到隔离位置，不写入正式远程目的地。

### 预览调度

输入变化后防抖触发可允许的预览；新请求取消旧请求，并通过 revision 丢弃过时结果。预览和媒体探测使用独立低优先级并发额度，不能挤占正式任务的全部 CPU 或 GPU。

## 12 执行计划和任务调度

### 任务数据

作业保存不可变工程快照、引擎指纹、实际 argv、输入引用、输出策略、子步骤、资源需求、日志位置、时间戳和终态。每次重试创建新的 attempt，保留原失败记录。

参数文件及已识别的 concat、sendcmd、字幕等文本依赖保存内容哈希。提交时默认复制到作业私有资源目录，并在实际 argv 中使用快照路径；需要实时读取的资源改为执行前校验，变化后使原验证失效。大媒体文件默认记录身份和修改信息，不全部复制；任务历史分别显示原资源与执行快照。

任务可包含探测、分析、第一遍编码、第二遍编码和产物验证等子步骤。步骤依赖由调度器管理，与 FFmpeg 内部滤镜图分开。

### 状态机

~~~mermaid
stateDiagram-v2
  [*] --> Draft
  Draft --> Validating
  Validating --> Draft: 发现需修改的问题
  Validating --> Queued: 校验通过
  Queued --> Starting
  Starting --> Running
  Starting --> Failed
  Running --> Finalizing: 进程正常结束
  Finalizing --> Succeeded: 产物提交完成
  Finalizing --> Failed
  Queued --> Canceled
  Running --> CancelRequested
  CancelRequested --> Canceled: 进程树退出
  Running --> Failed: 进程异常退出
  Running --> Recovering: 应用重启后检查
  Recovering --> Orphaned: 原进程仍在或身份未确认
  Recovering --> Interrupted: 确认原进程已退出
  Orphaned --> Interrupted: 所属进程退出或安全终止
~~~

Starting、Finalizing 等非终态也允许取消或恢复判定；实现以完整转换表测试为准。CancelRequested 后的自然完成、提交和取消通过互斥终态裁决处理，避免同时显示成功和取消。

重启后，未启动作业保留排队状态，原 Running 等未完成状态进入 Recovering。首期进程内 Runner 无法重新接管崩溃前的标准流；发现可能存活的原进程时进入 Orphaned，并持续占用原输出互斥锁，禁止自动重试。核对启动时间、二进制身份和作业归属后，可等待退出或安全终止；身份未确认时交由用户处理，不能只按旧 PID 杀进程。确认原进程退出后才能转 Interrupted 并创建新 attempt。Finalizing 的恢复另外读取提交 journal，不能直接重跑已提交产物。

### 并发和恢复

默认一个正式任务并发，用户可配置 CPU 与 GPU 额度。相同输出目标互斥，硬件编码器和设备按资源键调度，防止预览与正式任务争抢独占设备。

普通转码中断后从头重跑。两遍编码等任务只有在子步骤完成、输入和引擎身份不变且中间产物验证通过时，才复用该步骤结果。直播重连创建新的 session。恢复工程、队列和记录不等于通用断点续转。

首期提供暂停队列和取消当前任务；进程挂起不作为跨平台可靠暂停功能，避免对直播、网络连接和设备任务作错误承诺。

### 进度和日志

优先使用 -progress 的 key=value 输出读取程序化进度，stderr 单独用于日志。stdout 不输出媒体时可以使用 pipe:1；stdout 已被媒体或其他输出占用时，改用受控独立进度文件或管道。

已有用户进度输出需要保留其意图，由计划决定共享、转发或使用仅日志模式；不能悄悄覆盖用户参数。关闭或改动进度通道不会改变媒体参数。

总处理时长可推导时显示估计进度，并标注估计；直播、循环输入、复杂时序图或时长未知时显示已处理时间、速度和活动状态。progress=end 或进程退出码 0 单独出现都不能代替产物提交验证。[FFmpeg 进度与 stdin 选项](https://ffmpeg.org/ffmpeg.html#Main-options)

### 取消

普通文件任务可以保留由 Runner 控制的 stdin，先发送 q 请求 FFmpeg 正常结束。取消已获接受后，即使 FFmpeg 返回 0 也按 Canceled 处理，默认不将部分结果提交为完整产物；已经完成提交的任务不能再追溯取消。

stdin 已承载媒体或用户明确使用 -nostdin 时，POSIX 使用已验证的信号路径。Windows 隐藏进程能否接受优雅控制事件需要专门验证；没有可靠通道时明确使用强制停止，并将产物标记为不完整。超时后终止整个受管进程组或进程树，不将 processGroup.kill() 等同于优雅收尾。

进程树管理使用 POSIX 进程组或 Windows Job Object 等机制。Tauri shell API 的 processGroup 可用于 kill 进程树，但具体退出、崩溃和优雅终止行为仍需跨平台测试。[Tauri Shell API](https://v2.tauri.app/reference/javascript/shell/)

## 13 输出文件和资源安全

### 输出提交策略

输出模型明确区分 LocalFile、DirectoryBundle、SequencePattern、Pipe 和 NetworkTarget。

普通本地单文件在同一目录写入唯一临时目标，显式保留实际 muxer 或可识别扩展名；进程成功、文件验证通过后再提交到正式位置。覆盖原文件采用平台文件 API，避免先删除后重命名导致原件丢失。

提交前先持久化 journal，记录临时产物身份、目标预期身份、覆盖备份和逐文件状态；文件替换后再记录完成并提交任务终态。启动恢复依据 journal 与实际文件身份对账，处理“文件已替换但数据库未标成功”的窗口，避免重复写入。需要的 flush 与平台替换语义纳入故障测试；未知提交状态保留现场，禁止直接覆盖重试。

目录输出、分片、序列和 tee 分别解析产物范围。可隔离的输出写入暂存目录；无法原子提交的多文件输出按清单提交。有覆盖备份时尝试回退，整体属于尽力回滚；未备份或不可逆目标不承诺恢复原件。未完成产物、清理失败和需要人工恢复的项在任务结果中可见。

网络和设备输出按实时会话管理，无法承诺文件式事务或撤回已发送数据。无法确定写入范围的输出在运行前显示这一限制，由用户明确选择直接运行或调整配置。

输入与输出比较规范化路径、符号链接和可获得的文件身份，防止覆盖源文件。队列内重名、磁盘空间、路径权限和已有文件冲突在执行前检查，执行时再次检查；探测不能消除执行时的资源变化。

### 进程和文件权限

Runner 只启动经用户选择和身份校验的 ffmpeg、ffprobe 以及明确允许的辅助工具。使用参数数组直接启动，不经 bash、PowerShell 或 cmd 拼接执行。前端 IPC 限制命令范围，Rust 层再次验证请求。

桌面壳的 capability 或文件 API 范围不自动沙箱化 FFmpeg。concat 清单、字幕字体、drawtext 文件、movie 源、网络协议和分片模板都可能间接访问资源；工程保存已识别外部资源，导入时不自动运行或联网。

限制模式可收紧协议和已知资源；完整高级模式允许用户启用需要的功能。若需要隔离不可信媒体或任意滤镜的系统级访问，应使用独立 OS 沙箱或容器执行配置，并验证其功能影响。[Tauri 安全边界](https://v2.tauri.app/security/)、[Capability 机制](https://v2.tauri.app/security/capabilities/)

### 凭证与隐私

网络密码、访问令牌等放入系统凭证存储，工程保存引用。默认分享导出和问题报告不包含凭证、完整敏感 URL 或私人绝对路径；用户导出可复现完整命令时显示其包含的敏感字段。

本地运行日志也可能带有未知插件输出的凭证或路径。按已识别字段脱敏并提供导出预览，不承诺任意 stderr 都能自动完全脱敏。临时文件使用用户私有目录，并提供保留期与清理入口。

## 14 工程和预设持久化

工程文件采用版本化 JSON，扩展名初定为 .ffgui.json，保存命令文档、展示布局、资源引用、引擎要求和预设来源。输入媒体默认不打包，跨机器打开时使用资源重定位向导。

SQLite 保存队列、attempt、事件序号、产物清单和恢复检查点。工程保存采用临时文件与替换，数据库迁移前备份；迁移失败允许回到原数据版本。

预设保存结构化参数模板、适用条件和变量定义。批处理变量如 {input.stem}、{index} 在 Runner 中按受控规则展开，不交给 shell。展开后重新校验路径、冲突及作用域。

首次保存敏感工程时提示凭证存储方式；普通保存和运行不反复要求无意义确认。

## 15 校验和错误处理

校验分为四层：

| 层级 | 内容 | 用户反馈 |
| --- | --- | --- |
| 参数语法 | 类型、单位、范围、枚举、复合语法 | 定位到字段或表达式位置 |
| 关系语义 | 作用域、流引用、端口、copy 与处理冲突 | 定位到参数、连接或输出流 |
| 环境条件 | 组件缺失、权限、设备、驱动、路径 | 给出可操作的修复入口 |
| 实际执行 | 编码失败、网络异常、磁盘耗尽 | 保留 stderr、退出状态和受影响产物 |

只有已确认的错误阻止运行。来自不完整规则或未知硬件的判断显示为待验证，提供安全的短样本验证或高级运行入口，不能把合法功能一律禁用。

离线检查不会覆盖所有 FFmpeg 条件。短样本验证必须单独说明读取范围、输出位置和与正式任务的差异；有副作用的任务不自动执行。日志诊断允许给出候选原因，但不能将模式匹配描述成确定结论。

错误发生后保留工程和参数，重试不要求用户重建任务。问题列表、日志与命令片段可以相互定位。

## 17 验收与测试

### 覆盖报告

每个受支持 BinaryProfile 生成覆盖清单，分别报告：

- 目录覆盖率：已展示参数定义数除以能力基线参数定义数。
- 结构化编辑覆盖率：具有经过验证的参数行或专用编辑器的定义数除以可配置定义数。
- 作用域规则覆盖率、复杂语法编辑器覆盖率和组件详情扫描完成率。
- 复合值内部覆盖率：结构解析、已知内层键和值校验分别以匹配组件版本的清单为分母，未知键单列。
- 未解析帮助条目、未知定义、尚未支持语法和环境不可用条目。
- 命令保真测试通过率与真实场景通过率。

分母来自二进制探测、匹配版本规则和组件清单的对账结果，不能仅统计解析成功的部分。基线本身未完成对账时显示“覆盖率待确认”。别名与规范参数分开计数，诊断调用不误算为媒体任务参数。

完整支持声明要求：固定参考构建中目录与结构化编辑覆盖率达到 100%，未解析条目和未解决作用域缺口为零，所有承诺语法有验证用例。专用拖拽控件的丰富程度单独报告，不把每个标量参数都要求设计一个独特面板。

### 命令和产物验证

测试语料覆盖：

- 多输入、多输出、不同位置的 -ss、重复累加与覆盖参数。
- 正向、排除、可选映射，复杂选择器，输入重排和输出流序号变化。
- 多个复杂滤镜图、动态端口、合法环路、回环解码器。
- 章节、元数据、附件、字幕、节目、流组和 BSF。
- 空值、负数值、Unicode、空格、引号、反斜杠、冒号及特殊文件名。
- 参数文件、复合字典、未知参数和 shell 不支持语法的保留。
- CLI 正负布尔开关与显式布尔 AVOption 的编码差异。
- 原生非 UTF-8 路径的选择、保存、重启、执行，以及跨平台重定位。
- 排队后参数文件发生变化、共享 libav 库被替换但版本号不变。
- 普通文件、序列、目录、多文件、网络、设备、管道和硬件输出。

可重复的 argv 样例要求逐 token 保真。真实短样本要求检查退出状态和产物，通过 ffprobe 核对流数量、格式、尺寸、时间、声道和元数据。适用时使用解码帧校验或 framemd5 比较；有损编码不以跨硬件字节完全一致作为普遍要求。

### 平台和故障矩阵

首期参考平台覆盖 Windows x64、macOS Apple Silicon 和 Linux x64；扩展验证 macOS Intel、Windows ARM64 和 Linux ARM64。每个平台固定一个受控发行构建，并测试至少一个自定义构建。实际发布支持范围由通过的矩阵确定。

硬件矩阵按条件验证 VideoToolbox、NVENC、QSV、VAAPI 等构建支持的路径。没有相应硬件的 CI 只验证目录与配置，不报告真实编码通过。

故障用例包括进程无法启动、扫描超时、组件缺失、权限拒绝、磁盘耗尽、网络断开、取消竞态、应用崩溃、残留进程、路径冲突和数据库迁移失败。单独注入提交前、文件替换后和数据库成功提交前的崩溃；验证父进程崩溃但旧子进程仍写文件、q 后零退出码、媒体 stdin、阻塞网络输入和 Windows 隐藏进程的取消。要求不误报成功、不覆盖源文件、不按复用 PID 杀错进程、不产生重复重试写入。

## 19 发布和开源许可

自有应用代码初步建议采用 Apache-2.0，便于复用并保留明确的贡献者专利授权条件。最终许可需要与所选 UI 依赖、辅助程序和实际发布内容一起核验。

FFmpeg 作为独立程序调用，发行包分别提供其许可证、对应源码获取方式和构建信息。基础 FFmpeg 通常采用 LGPL-2.1-or-later；启用部分 GPL 组件会改变构建许可。独立进程调用不自动决定整个产品的许可边界，仍需按实际代码复用、通信和分发方式判断。

初期开发优先支持用户选择已安装引擎。提供内置构建前，固定可复现的构建配置，记录外部库清单，并核对 enable-gpl、enable-nonfree 等选项与分发条件。应用升级与 FFmpeg 引擎升级分开，工程打开时显示能力差异，不自动删除消失的参数。[FFmpeg 官方许可说明](https://ffmpeg.org/legal.html)、[Apache-2.0](https://www.apache.org/licenses/LICENSE-2.0)、[GNU 关于独立程序的说明](https://www.gnu.org/licenses/gpl-faq.en.html#MereAggregation)
